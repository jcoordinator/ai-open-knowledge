## ❓ Why AI Open Knowledge?

Artificial Intelligence is evolving faster than any technology in history — but the knowledge needed to keep up is **scattered, fragmented, and often locked behind paywalls**.

### The Problems Today

| Problem | Reality |
|---|---|
| 🧩 **Fragmented resources** | Great content exists — but it's spread across thousands of blogs, papers, videos, courses, and repos with no unified structure. |
| ⚡ **Rapid AI evolution** | Techniques become outdated within months. LLMs, agents, RAG, and MCP move faster than any single curriculum can track. |
| 🌫️ **Knowledge scattered** | Beginners don't know where to start; practitioners waste hours re-discovering what others already documented. |
| 💰 **Paywalls and gatekeeping** | High-quality AI education is often expensive, excluding students and developers in many parts of the world. |
| 🏝️ **Isolated learning** | Most people learn AI alone, without a community to review, discuss, and improve their understanding. |

### The Solution

**AI Open Knowledge** solves this through:

- 🤝 **Community collaboration** — hundreds of contributors keep content accurate, current, and battle-tested.
- 🔓 **Open source** — everything is transparent, versioned, reviewable, and forever free.
- 🗂️ **Organized structure** — a single, well-designed taxonomy covering the entire AI landscape.
- 🔄 **Continuous updates** — pull requests keep pace with the field, so knowledge never goes stale.
- 🌍 **Global accessibility** — anyone with an internet connection can learn, use, and contribute.

> [!TIP]
> Think of this repository as a **living encyclopedia of practical AI knowledge** — maintained like software, versioned like code, and open like the web should be.

## 🚀 How To Use

> [!TIP]
> You don't need to read everything. Pick your entry point based on **who you are** and **what you need**.

1. **🌱 New to AI?**
   Start at [`./ai-fundamentals/`](./ai-fundamentals/), then follow the **Beginner** path in [`./learning-paths/`](./learning-paths/). Keep the [`./glossary/`](./glossary/) open in another tab.

2. **🎯 Have a specific goal?**
   Use the [Complete Repository Navigation](#-complete-repository-navigation) table to jump directly to your topic — for example [`./rag/`](./rag/) if you're building a retrieval pipeline.

3. **🛠️ Building something right now?**
   Grab a starting point from [`./templates/`](./templates/) or [`./examples/`](./examples/), and check [`./workflows/`](./workflows/) and [`./prompts/`](./prompts/) for reusable pieces.

4. **📚 Studying for interviews?**
   Head to [`./interview/`](./interview/) and reinforce weak areas with [`./cheatsheets/`](./cheatsheets/).

5. **🔍 Looking for something specific?**
   Use GitHub's built-in search (<kbd>/</kbd> on the repo page) — every document is plain Markdown and fully searchable.

6. **⭐ Want to stay updated?**
   Star and watch the repository, and check [`CHANGELOG.md`](./CHANGELOG.md) for notable additions.

## 🤝 Contribution

**Contributions are the heart of this project.** Whether you fix a typo, add a tutorial, translate content, or design a whole new learning path — you make AI knowledge more accessible for everyone.

📘 **Read the full guide:** [CONTRIBUTING.md](./CONTRIBUTING.md)

### Contribution Workflow

```bash
# 1. Fork the repository on GitHub

# 2. Clone your fork
git clone https://github.com/YOUR-USERNAME/ai-open-knowledge.git
cd ai-open-knowledge

# 3. Create a feature branch
git checkout -b add/rag-evaluation-guide

# 4. Make your changes (add or improve content)

# 5. Commit with a clear message
git commit -m "docs(rag): add evaluation guide for RAG pipelines"

# 6. Push and open a Pull Request
git push origin add/rag-evaluation-guide
```

### What You Can Contribute

- ✍️ New guides, tutorials, and explanations
- 🔗 High-quality curated resources
- 💬 Prompts, skills, and agent patterns
- 🐛 Fixes for outdated or incorrect content
- 🌍 Translations
- 💡 Ideas — open an issue to discuss before writing

> [!IMPORTANT]
> All contributions are reviewed for **accuracy, clarity, and neutrality** before merging. See [CONTRIBUTING.md](./CONTRIBUTING.md) for content standards.

## 💬 FAQ

<details>
<summary><b>1. Is this really free?</b></summary>

Yes — completely and permanently. All content is open source under the terms of the [LICENSE](./LICENSE). No paywalls, no premium tiers, no sign-ups.
</details>

<details>
<summary><b>2. I'm a complete beginner. Where do I start?</b></summary>

Start with [`./ai-fundamentals/`](./ai-fundamentals/) and follow the **Beginner** path in [`./learning-paths/`](./learning-paths/). Keep the [`./glossary/`](./glossary/) handy for unfamiliar terms.
</details>

<details>
<summary><b>3. How is content kept up to date?</b></summary>

Through the community: contributors submit pull requests when techniques evolve, and maintainers periodically review high-traffic sections. Outdated content can be flagged via issues.
</details>

<details>
<summary><b>4. Can I use this content in my courses, blog, or company training?</b></summary>

Yes, in accordance with the [LICENSE](./LICENSE). Attribution is appreciated. Educators are explicitly encouraged to build on this material.
</details>

<details>
<summary><b>5. How do I contribute if I've never contributed to open source before?</b></summary>

Perfect — this is a great first project! Read [CONTRIBUTING.md](./CONTRIBUTING.md), look for issues labeled `good first issue`, and start with something small like fixing a typo or adding a resource link.
</details>

<details>
<summary><b>6. Do contributions need to be in English?</b></summary>

English is the primary language, but translations are welcome and encouraged. See [CONTRIBUTING.md](./CONTRIBUTING.md) for translation guidelines.
</details>

<details>
<summary><b>7. Is this repository vendor-neutral?</b></summary>

Yes. We cover tools and models from all providers — open-source and commercial — objectively, based on evidence and community experience. No paid placements, ever.
</details>

<details>
<summary><b>8. What's the difference between <code>prompts/</code> and <code>prompt-engineering/</code>?</b></summary>

[`./prompt-engineering/`](./prompt-engineering/) teaches the **techniques and science** of prompting. [`./prompts/`](./prompts/) is a **library of ready-to-use prompts** you can copy directly.
</details>

<details>
<summary><b>9. What is MCP and why does it have its own folder?</b></summary>

The Model Context Protocol is an open standard for connecting AI models to tools and data sources. It's becoming foundational for agent systems, so [`./mcp/`](./mcp/) covers servers, clients, and integration patterns in depth.
</details>

<details>
<summary><b>10. Can I request a topic that doesn't exist yet?</b></summary>

Absolutely — open an issue describing the topic and why it matters. If it fits the taxonomy, it will be added to the [ROADMAP.md](./ROADMAP.md) or you can contribute it yourself.
</details>

<details>
<summary><b>11. How is content quality ensured?</b></summary>

Every pull request goes through review for accuracy, clarity, sourcing, and neutrality. CI checks validate links and formatting. Community feedback via issues catches anything that slips through.
</details>

<details>
<summary><b>12. Does this repository include code, or only documentation?</b></summary>

Both. Most content is Markdown documentation, but [`./examples/`](./examples/), [`./projects/`](./projects/), and [`./templates/`](./templates/) contain runnable code and starter kits.
</details>

<details>
<summary><b>13. How do I report incorrect or outdated information?</b></summary>

Open an issue with the file path and a description of the problem — or better, submit a pull request with the fix.
</details>

<details>
<summary><b>14. How do I report a security concern?</b></summary>

Please follow the responsible disclosure process described in [SECURITY.md](./SECURITY.md). Do not open public issues for security vulnerabilities.
</details>

<details>
<summary><b>15. Who maintains this project and how are decisions made?</b></summary>

The project is governed by a team of maintainers with community input. Roles, responsibilities, and decision-making processes are documented in [GOVERNANCE.md](./GOVERNANCE.md).
</details>

## 🏆 Best Practices

Content in this repository follows — and teaches — these principles:

- ✅ **Cite sources** — claims link to papers, docs, or reproducible evidence
- ✅ **Show, don't just tell** — concepts come with examples and code where possible
- ✅ **Stay current** — dated content is marked and refreshed
- ✅ **Start simple** — every topic offers a beginner-accessible entry point
- ✅ **Be practical** — theory is always connected to real-world application
- ✅ **Remain neutral** — tools and models are compared on evidence, not hype
- ✅ **Think security-first** — engineering content addresses safety and security implications
- ✅ **Keep it maintainable** — consistent structure and naming across all folders

Find dedicated best-practice guides throughout the repository, especially in [`./ai-engineering/`](./ai-engineering/), [`./ai-security/`](./ai-security/), and [`./evaluation/`](./evaluation/).

## 📈 Recommended Order of Learning

A pragmatic route from zero to advanced AI practitioner:

1. **🧱 Foundations** — [`./ai-fundamentals/`](./ai-fundamentals/) + [`./glossary/`](./glossary/) — understand what AI is and speak the language
2. **➗ Mathematics** — [`./mathematics/`](./mathematics/) — linear algebra, probability, and calculus essentials
3. **👨‍💻 Programming** — [`./programming/`](./programming/) + [`./computer-science/`](./computer-science/) — coding skills for AI work
4. **📈 Machine Learning** — [`./machine-learning/`](./machine-learning/) — classical algorithms and core theory
5. **🧠 Deep Learning** — [`./deep-learning/`](./deep-learning/) — neural networks and modern architectures
6. **💬 NLP** — [`./nlp/`](./nlp/) — language understanding foundations
7. **🗣️ LLMs** — [`./llms/`](./llms/) — how large language models work and how to use them
8. **✍️ Prompt Engineering** — [`./prompt-engineering/`](./prompt-engineering/) + [`./prompts/`](./prompts/) — communicate with models effectively
9. **📡 RAG** — [`./rag/`](./rag/) + [`./vector-databases/`](./vector-databases/) — ground models in your own data
10. **🤖 Agents** — [`./agents/`](./agents/) + [`./mcp/`](./mcp/) + [`./workflows/`](./workflows/) — build autonomous AI systems
11. **🎛️ Fine-Tuning** — [`./fine-tuning/`](./fine-tuning/) — adapt models to your domain
12. **⚙️ AI Engineering** — [`./ai-engineering/`](./ai-engineering/) + [`./evaluation/`](./evaluation/) + [`./model-serving/`](./model-serving/) — ship to production
13. **🛡️ Safety & Security** — [`./ai-safety/`](./ai-safety/) + [`./ai-security/`](./ai-security/) — build responsibly
14. **🔬 Research & Beyond** — [`./papers/`](./papers/) + [`./research/`](./research/) + [`./future-topics/`](./future-topics/) — push the frontier

> [!NOTE]
> This order is a suggestion, not a rule. Skip ahead if you already have the prerequisites — every section stands on its own.
